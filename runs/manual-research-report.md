# Lightweight Agent Stacks 2026 — Brief Comparison

> **Generated by:** Cursor agent (manual research run)  
> **Date:** 2026-08-23  
> **Tools:** web_search, fetch_url, save_note, submit_report (5 steps)

## Summary

For **structured agent tasks** (search → fetch → synthesize → deliver), a strong **20–30B model** is often enough. Frontier (70B+) is justified when you need deeper reasoning, fewer hallucinations in gray areas, or complex multi-step planning — but usually requires **more step budget** in the agent loop.

**Recommendation:** Start with **LangGraph** or **smolagents** + **Qwen3-30B** or **gpt-oss-20b** via **OpenRouter**, and escalate to frontier only when lightweight fails in evaluation.

## Frameworks (4 compared)

| Framework | Strength | Weakness | Choose when… |
|---------|--------|---------|-----------|
| **LangGraph** | Explicit state, durable graphs, retries, human-in-the-loop | More boilerplate, steeper learning curve | You build production agents with complex flows |
| **smolagents** | Minimal code, CodeAct, HF-integrated | Fewer enterprise features out of the box | You want to prototype quickly with Python/code-heavy agents |
| **OpenAI Agents SDK** | Compact, handoffs, MCP, sandbox, tracing | OpenAI-centric | You primarily run OpenAI models and want the official SDK |
| **CrewAI** | Role-based teams, intuitive for multi-agent | Can get heavy for simple loops | The task naturally splits into roles (researcher, writer, reviewer) |

All four follow the same core pattern: **model + tools + loop**. The difference is how much orchestration you get for free vs. how much you define yourself.

## Model Size: 7B–30B vs Frontier (70B+)

| Dimension | 7B–20B | 20B–30B (MoE) | 70B+ frontier |
|-----------|--------|---------------|---------------|
| **Cost** | Lowest (~$0.03–0.10/M in) | Low (~$0.05–0.20/M in) | High ($1–15/M in) |
| **Latency** | Fastest | Fast | Slower |
| **Tool-calling** | Good with the right model | **Sweet spot** | Most robust |
| **Synthesis/quality** | Shallower | Sufficient for structured research | Best in gray areas |
| **Agent loop** | Aggressive, fewer tokens/step | **Best price/performance** | More cautious, needs more steps |

**Practical rule:**

- **20–30B is enough** for: research reports, data extraction, API orchestration, tool-augmented customer support.
- **Frontier is needed** for: legal/medical analysis, complex planning, high-stakes tasks where errors are costly.

OpenRouter shows that the same model (e.g. Llama 3.3 70B) can cost **$0.10–$1.00/M input** depending on provider — routing matters.

## Inference Providers (2026)

| Provider | Why | Best for |
|----------|--------|------------|
| **OpenRouter** | One API, 400+ models, auto-failover, price comparison | Experimentation + production with model flexibility |
| **Groq** | Extremely low latency (custom silicon) | Real-time agents, fast tool loops |
| **Together AI** | Broad model catalog, fine-tuning + inference | Teams that want to own the full stack |
| **Fireworks AI** | Optimized serving, production SLAs | Production agents with uptime requirements |

## Conclusion & Recommendation

| Scenario | Stack |
|----------|-------|
| **Prototype / cheap research** | smolagents + Qwen3-30B via OpenRouter |
| **Production with complex state** | LangGraph + 20–30B, escalate to Sonnet when needed |
| **OpenAI-native** | OpenAI Agents SDK + GPT-4.1 mini/4.1 |
| **Multi-agent team** | CrewAI + 30B per role |

**Bottom line:** Invest in **tools, prompts, and step budget** before model size. A good 30B with aggressive tool use often beats a frontier model stuck in a narrow loop — but frontier wins when you give it enough steps and a harder task.
