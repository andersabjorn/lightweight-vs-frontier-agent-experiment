## Framework Comparison

### 1. LangGraph
- **Architecture**: Graph-based with nodes and edges
- **Strengths**: Production-grade, stateful workflows, deterministic control, human-in-the-loop
- **Use case**: Complex multi-step systems requiring state persistence
- **Overhead**: Higher than alternatives but more control

### 2. smolagents (Hugging Face)
- **Architecture**: Code-centric, minimal abstraction
- **Strengths**: CodeAgent writes Python directly, near-zero overhead, inspectable codebase
- **Use case**: Small experiments, developers who want minimal abstraction
- **Installation**: `pip install 'smolagents[toolkit]'`

### 3. OpenAI Agents SDK
- **Architecture**: Lightweight primitives (agents, tools, handoffs, guardrails)
- **Strengths**: Fast prototyping, optimized for the OpenAI ecosystem
- **Use case**: Teams already integrated with OpenAI
- **Limitation**: Less fine-grained workflow state control

## Model Sizes (7B–30B)

### Performance vs Cost
- **7B–13B**: Most cost-effective for simple quantitative tasks
- **20B–30B**: Balance between performance and efficiency
- **MoE models** (e.g. GPT-OSS-20B): 32% higher throughput, 26% lower energy use vs dense 30B–34B

### Break-even Analysis
- **Qwen3-30B**: Cost parity with APIs at ~0.3 months
- **Llama-3.3-70B**: Cost parity at ~2.3 months

## Inference Providers

### Primary Choices
1. **Together AI**: Broadest model catalog, full-stack (training, fine-tuning, hosting)
2. **Groq**: Highest throughput with LPUs, best for streaming/real-time

### Specialized
- **Fireworks AI**: Lowest P99 latency, optimized serving stacks
- **Replicate**: Standard for custom/niche models, container-based
- **Anyscale**: Enterprise-grade, Ray-based for complex pipelines

## Recommendation: When Is 20–30B Enough vs Frontier?

### 20–30B Models Are Enough For:
- **~80% of enterprise workloads**:
  - Classification and extraction
  - Domain-specific RAG
  - Structured data processing
  - Domain-scoped code generation

### Frontier Models Are Needed For:
- Open-ended, complex reasoning
- General capability as the primary value axis
- Unknown/unpredictable tasks

### Cost Strategy for 2026:
1. **Task routing**: Use the smallest model that meets the accuracy threshold
2. **Multi-provider**: Groq for latency-sensitive, Together AI for steady-state, Replicate for niche
3. **Self-hosting**: Economical at predictable volume beyond ~0.3–2.3 months

## Conclusion

For 2026, the strategy is **hybrid routing** rather than one-size-fits-all. Combine lightweight frameworks (smolagents for experiments, LangGraph for production) with 20–30B models for most tasks, reserving frontier only for complex reasoning.
